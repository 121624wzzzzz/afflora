# 方法与解释边界

## 研究问题

本轮测试普通内部 LoRA 加输入/输出边界 A-LoRA，是否在两项新任务上比普通 LoRA及同总参数的内部 LoRA有额外收益。只设置这三个适配方案和未微调 Base，不据此推断单侧模块效果或最佳放置方式。

普通 LoRA / 两种扩容方案的可训练参数分别为：0.6B 模型 5,046,272 / 5,112,832；1.5B 模型 9,232,384 / 9,332,224。所有原权重冻结。等参数内部 LoRA 在固定 q/k 投影增加一个 rank，共有 r8 初始化和 alpha/r=2 缩放保持不变。A-LoRA 以 r16、alpha128 放在输入 embedding 输出与最终 lm_head 输入处，输入侧含偏置。两个模型都使用原生 tied 权重；参数效率和物理合并能力是不同问题。

## ANLI R1

官方 train/dev/test 均来自 ANLI v1.0。数据审计发现不同分区复用前提，因此在任何模型运行前排除训练池里出现在 dev/test 的前提，得到 6255 条候选，去重后6252条，固定抽2048条训练。开发与测试各保留全部1000条，不据开发分数调参；二者仍共享274个标准化前提，不能当作两个独立数据集累加证据。

输入仅为任务说明、前提、假设。主指标是固定三个单 token 标签 A/B/C 的概率最大项，分数不包含 EOS，也不依赖生成答案解析。报告中需称为标签准确率，不能称自由生成推理正确率。训练为标签加原生EOS的SFT，未训练思维链。全词表下一token命中率、标签概率质量及类别混淆作为诊断。该设置无法支持通用推理提升的主张。

## WikiSQL

任务是将问题和编号列名/类型转为官方 sel/agg/conds 查询逻辑形式，随后在官方表数据库执行；不是自由SQL字符串生成，不包含连接、多表或复杂SQL。没有给模型表内容、示例行、标准查询、执行答案；评测代码用到的标准答案和数据库不进入模型提示。

官方分区的表ID不重叠；再按标准化提示去重并按固定哈希抽样，train2048/dev256/test1024。测试含928张表，所有选中标准查询执行结果非空。该子集和小数据训练设置不能作为完整WikiSQL排行榜分数。

主要指标遵循固定官方DBEngine的执行结果列表相等，逻辑形式按官方 Query 的条件集合规则比较。首个JSON对象可被解析，允许markdown围栏或尾部解释，但严格JSON率另记；模型预测的三字段结构、列索引及操作符必须有效。无法解析、无效查询、执行失败和截断均保留分母。

官方DBEngine对同列多个条件复用参数名；本轮全部标准查询均无此情形。仍对预测记录重复条件列比例，并补充使用独立参数的执行得分，保证这个参考实现细节透明。正式指标不因观察结果而更改。所有有效预测最后再次调用未修改的官方执行器和Query类核对。参考库 records0.5.3 与 SQLAlchemy1.3.24 安装在本目录，不改动全局实验环境。

## 共同训练、评测与统计

两个模型均为已验证的官方预训练Base。每方案五个种子7100–7104，2048样本、单轮64步、共同学习率2e-4、有效batch32/microbatch4。普通LoRA r8/alpha16/dropout0.05，边界层dropout0。AdamW、3%预热/余弦、梯度裁剪1；只对答案和EOS求token平均损失。冻结原模型BF16、适配器及优化器FP32，训练BF16 autocast；评测统一FP32、batch16、TF32关闭。WikiSQL贪心最多256token；标准目标最多65token。ANLI用标签logit比较。所有输入完整保留，无截断。

固定末步，无开发集选模型或学习率。训练和评分代码、数据与统计规则在任何模型输出前冻结。中间进度曾被查看，但方案未据分数改变；不能表述为整个过程中测试输出一直不可见。原始Base文件和复用代码哈希已核对，不复用此前已训练adapter。

本轮四个任务/模型组合各与两个对照比较，共八项预定主比较，以五种子配对差值的Bonferroni校正双侧95% t区间衡量训练变异。题目/前提/表簇bootstrap以已训练五模型为条件，仅作补充，不能替代种子区间。分格式、类别、聚合函数等分析为事后描述，不另作显著性筛选。

尚未独立调优每个方案的学习率、训练轮数和等参数内部rank放置，也没有跨模型家族验证；公共数据的预训练暴露未知。正结果支持这些固定条件下的叠加增量，不能证明所有任务普遍占优；跨零区间亦不能证明真实效应严格为零。
