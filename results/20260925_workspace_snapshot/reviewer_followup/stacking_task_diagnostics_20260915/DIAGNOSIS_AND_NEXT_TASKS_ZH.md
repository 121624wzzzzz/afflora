# IFEval 波动诊断与下一组任务建议

日期：2026-09-15。本次完成的是既有结果的只读诊断与任务设计，尚未运行下面建议的新基准。原训练、清单和结果保持原样。逐样本统计及来源 SHA-256 见 [DIAGNOSTICS.json](DIAGNOSTICS.json)，重算程序见 [diagnose.py](diagnose.py)。

目前可以确认：双边边界适配叠加 hidden LoRA 后，中文对话测试 CE 有小而一致的改善；英文为主的 IFEval 尚无稳定额外收益。不能将后者概括为所有生成任务都没有收益，也不能将 CE 改善直接写成回答正确率提升。

**最需要补上的对照是同语言、答案可客观判分的任务。** 先使用已经核验的 checkpoint 做中文问答与阅读理解迁移评测，再用独立的任务内训练检验“同样训练预算下，叠加是否让答案更正确”。这两个问题须分别报告。

本次新发现的事实如下。

| 项目 | 只读检查结果 | 可以说明什么 |
| --- | --- | --- |
| SFT 训练 | 22,780 条对话中，22,778 条的汉字占字母类字符超过 50%；assistant 目标满足该条件的有 22,765 条 | 训练实际以中文为主 |
| CE dev/test | 各 1,000 条对话及其 assistant 目标全部满足上述条件 | CE 测量的是中文对话分布 |
| IFEval 提示 | 541 条中仅 1 条包含任何汉字，没有一条汉字占比超过 10%；提示主体为英文 | 当前生成测评同时跨了语言与任务 |
| 训练后 IFEval 输出 | 24 个训练端点均无汉字占比超过 10% 的回答，去掉显式 language 指令也一致 | 没有看到大量改用中文回答的现象；不能将错配简单解释为“输出语言错了” |

汉字占比是字符启发式，不是正式语言识别器。训练源是 MiniMind 的 `sft_t2t_mini_25k`；训练对话内容与上述统计一致。当前更准确的实验描述是“中文对话建模改善是否迁移到以英文提示为主的约束遵循”，不是同分布生成质量检验。这个错配是需要检验的原因假设，尚不是已经确认的因果解释。

**CE 改善分布较广，但幅度不足以保证生成决策改变。** 下表均比较 both 与 none；none 在此代表仅 hidden LoRA，不是未微调模型。

| 模型 | seeds 42 / 43 / 44 中 CE 降低的测试样本数，每次共 1,000 条 | 平均 CE 降低 | 正确 token 条件概率的几何均值相对增加 |
| --- | --- | ---: | ---: |
| Qwen3-0.6B | 813 / 775 / 787 | 0.0054165 | 约 0.543% |
| Qwen2.5-1.5B-Instruct | 873 / 864 / 888 | 0.0068795 | 约 0.690% |

最后一列逐种子按 `100 × (exp(CE_control − CE_both) − 1)` 计算后平均，沿用原 CE 的 token 权重与标准答案前缀。它是相对概率变化，不是准确率百分点。逐样本降低计数不证明每条样本都有统计显著性，但显示改善并非只来自极少数测试样本。

例如正确 token 概率从 0.300 变为 0.302，而最高分错误 token 仍为 0.400，CE 会改善，greedy 选择仍然错误。即使某一步改变了选择，后续生成也以自身输出为前缀，和 CE 的标准答案前缀不同。因此不能预期两个指标严格同涨同跌。

**IFEval 的变化是双向的，净差较小。** 官方任务围绕可自动验证的指令约束，涵盖长度、关键词等；prompt strict 要求该题所有指令通过。它提供约束遵循证据，不等于完整的语义质量或事实正确率。[IFEval 原论文](https://arxiv.org/abs/2311.07911)

| 模型 / 种子 | both 从失败变通过的题数 | both 从通过变失败的题数 | 净增加通过题数 |
| --- | ---: | ---: | ---: |
| Qwen3 / 42 | 20 | 26 | -6 |
| Qwen3 / 43 | 26 | 21 | +5 |
| Qwen3 / 44 | 29 | 23 | +6 |
| Qwen2.5 / 42 | 27 | 27 | 0 |
| Qwen2.5 / 43 | 23 | 29 | -6 |
| Qwen2.5 / 44 | 21 | 22 | -1 |

两个模型分别每种子平均有 48.3、49.7 道题 strict 得分改变，而平均净变化仅 +1.67、-2.33 道题。原报告主要对比的种子区间和配对题目区间都包含零。看到这种抵消后，三种子均值的正负变化并不反常。

截断也不是全部解释。比如 Qwen2.5 seed 43，双方均未触及 token 上限的回答中仍有 17 道改善、27 道退步。这里的“双方均未截断”由模型输出决定，仅用于描述得分变化，不能据此估计消除截断后的因果收益。各指令类别的事后统计都保留在 JSON，不能只挑正向类别当成新确认的结果。

另外，仅 hidden LoRA 微调后，IFEval strict 相对未微调参考平均下降约 7.76 个百分点（Qwen3）和 4.93 个百分点（Qwen2.5），幅度超过边界叠加的净差。这与任务迁移受损相容，但语言、数据风格、训练强度等因素尚未被独立操纵，不能确认其中某个因素就是原因。现有证据也不能支持“调一次解码参数就必然解决”。

建议的任务选择与证据角色如下；选择基于语言和测量目标，不以是否产生正结果作为保留标准。

| 优先级 | 任务 | 主要指标 | 对论文的作用 |
| --- | --- | --- | --- |
| 第一轮 | CMRC2018 中文篇章问答 | 自回归生成答案的 EM、F1；二者平均值作为主要任务分数 | 直接检验生成的短答案是否更准确 |
| 第一轮 | C³ 中文选择式阅读理解，dialogue 和 mixed 都覆盖 | 条件似然选项准确率；正确选项与最强错误选项的分差 | 检验概率改善是否转成答案排序改善；不能单独宣称自由生成收益 |
| 第二轮，独立任务训练 | CLUENER2020 中文实体识别 | 实体类型与文本跨度匹配的 F1，另报格式有效率 | 检验边界适配能否在明确的词汇/实体输出任务上带来额外收益 |

CMRC2018 官方任务的答案来自给定中文篇章中的连续片段，使用 EM 和字级 F1。这里建议用语言模型直接生成答案，再使用官方评分逻辑；这不是把模型改成原始 span classifier。[官方任务和指标](https://hfl-rc.com/cmrc2018/task/)

C³ 官方发布 dialogue、mixed 两类数据及 train/dev/test。用完整候选答案的条件似然做决策，可以避免把自由生成的长解释和答案抽取器混入主要准确率。[官方数据仓库](https://github.com/nlpdata/c3)

CLUENER2020 是带实体类型与跨度标注的中文细粒度实体识别任务。将其序列化成自回归生成是本次建议的实验形式，不是官方原始基线设置；应预先固定跨度表示、重复实体处理及评分器，并单独报告解析失败。[官方数据与标注说明](https://github.com/CLUEbenchmark/CLUENER2020)

第一轮可以复用当前全部 24 个训练端点与 2 个未微调参考：两个模型、四组实验臂、三个种子。无需重新训练，即可检验中文任务迁移。主要对比仍是 both−hidden 与 both−hidden_budget；output 臂提供补充消融。必须两项对比一起报告，避免只超过普通 hidden 就归因为边界位置。

正式评测前应固定以下事项并保存独立清单：

1. 数据下载来源、版本和 SHA-256；检查与已有 SFT 数据的精确重叠并保存记录。该检查不排除预训练污染或语义近重复。
2. 使用训练来源的样本调试模板、分词边界、评分器和长度处理。CMRC 的公开 dev 若用作本轮最终评测集，就不得再拿它选择提示或超参数；明确标注为 public-dev evaluation，不称作官方隐藏 test。C³ 保留独立最终 test。
3. 全部模型使用各自原生 no-thinking 模板，全部实验臂使用相同提示、解码和长度规则。CMRC 使用固定 greedy、直接答案输出与官方归一化评分；保存原始回答、截断率、答案 token 的 CE/top-1。多标准答案的 CE 聚合规则在看结果前固定。
4. C³ 主要选项分数固定为候选答案 token 的平均 log probability；总 log probability 作为预先声明的敏感性分析，二者全部报告。保留原选项顺序、正确选项分差和全部候选分数；标签生成如另做，单独作为指标，不混同于似然准确率。
5. 逐样本配对并报告三种子效应及区间；CMRC/C³ 多题共享同一篇章，重采样应以篇章为簇，而不是假装所有问题独立。三种子与题目采样的不确定性分别说明；多个主要对比作相应校正或明确作为探索性区间。
6. 重用前核实基础模型和 adapter 身份、配置与哈希，重载后在固定样本上重现已保存的 CE。沿用已有审计的明确范围与例外记录，不因文件名相同就默认可复用。
7. 保存全部任务和实验臂的结果，保留现有 IFEval 作为英文约束迁移对照。不给负结果换名称，不以新任务较好为由覆盖旧结果。

如果要把“额外 token 建模收益”扩展成“任务训练后的额外生成收益”，更强的补充是另建 CMRC 与 CLUENER 的独立训练实验。各臂从同一已核验基础模型开始，在对应任务的 train 上训练，使用一致的数据顺序、训练步数、选择规则和调参预算；继续保留两个模型、三个种子和等参数对照。这回答任务内适配的问题，与现有中文通用对话 adapter 的迁移评测分开建表。CLUENER 的公开验证标签若作为最终评测，也需从训练集另划开发集。

这份文件是事后诊断及下一轮设计建议，不是已经完成的新任务实验或正式预注册。尚未冻结的数据版本、模板细节和训练超参数必须在获取新评测结果前落盘。新任务同样可能没有收益；若答案 CE 改善而 EM/F1/选项准确率不变，应继续把主张限制在概率建模层面。若两项主要对比在多个任务及种子上都改善，才有依据将主张扩大为任务级额外收益。
