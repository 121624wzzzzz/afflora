# 效果评测 v2：明确每个指标在回答什么

本文件更新评测与报告规范；旧 CMRC/C3/IFEval 指标及所有正负结果保留。新增诊断基于已看过结果的 checkpoint 与数据，不升级为新的确认性主结果。具体核验结果见本目录最终报告。

**建模能力与任务效果应各有主列。**

| 要回答的问题 | 应报告的指标 | 解释边界 |
| --- | --- | --- |
| 相同预算下，平均内容 token 是否预测得更好？ | Content micro CE、content top-1；total CE 与结束符单列 | 对长答案给予更多权重；不是每题准确率 |
| 一道随机抽取的问题，平均答案 token 是否预测得更好？ | Question-macro content CE | 对短答案中的每个 token 权重更大；与 micro 不同 |
| 模型是否给可接受的完整答案分配更多概率？ | 去重参考答案集合 NLL，包含训练使用的结束符 | 只覆盖已标注字符串，非全部语义等价答案；仍不等于 greedy 准确率 |
| 实际生成是否更正确？ | 官方 EM、F1 各自列出；旧 AVG 汇总继续保留 | 回答序列的离散任务指标，不能由 CE 替代 |
| 小幅均值能否跨训练复现？ | 全部配对种子差值和种子区间 | 三种子估计方差不稳，区间含零不证明零效应 |
| 固定这几个训练结果，评测篇章采样是否影响结论？ | 配对篇章簇 bootstrap | 条件于已拟合模型，不能替代训练种子不确定性 |

**统一 CE 的分母。** 设第 i 个参考答案有 L_i 个内容 token，内容 NLL 为 S_i。

- micro CE = sum(S_i) / sum(L_i)，度量平均 token。
- macro CE = mean(S_i / L_i)，度量平均参考；本 CMRC 数据每题恰有三个参考，因此等价于先每题平均参考、再平均题目。
- total CE = [sum(S_i) + sum(EOS_NLL_i)] / [sum(L_i) + N]。

在每个对照与种子内，长度完全相同，所以有严格恒等式：

`Δmicro − Δmacro = Cov(L_i, Δ(S_i/L_i)) / mean(L_i)`。

这允许判断两个汇总的分歧是否来自长度权重，无需归因于实现错误。两者都合理，取决于研究问题；看到哪种为正就只采用哪种会造成选择偏差。

例如（以下为说明用假设数字），2-token 答案每 token 变差 0.010，20-token 答案每 token 改善 0.004：macro 变差 0.003，micro 却改善约 0.00273。没有任何概率被算错，只是两种平均在衡量不同对象。实际数据的全部四个长度桶 1–4、5–8、9–16、17+ 应一并保留。

**内容与结束行为使用同一前向分解。** 将内容进一步分成第一个答案 token 和其余 token，可得到 `total CE = first contribution + later contribution + EOS contribution`。各项共用总监督 token 数作为分母，差值可精确相加。不能把“每题一个 EOS 的平均 CE”直接加到“每个内容 token 的平均 CE”上。

内容 CE 改善不等于首个答案选择更准。首 token top-1、后续 token top-1 与 logit margin 作为诊断完整报告，而非挑选最有利的 token 子集重新定义主效果。这也不能独自证明 output/input 适配机制。

**完整参考集合概率保留答案之间的“或”关系。** 对去重后的参考字符串集合 Y：

`AnswerSetNLL(x) = -log sum_{y in Y} p(y, im_end | x)`。

计算时用稳定 logsumexp。EOS 让不同完整答案成为互斥序列事件；仅把不含结束符的前缀概率相加，遇到某答案是另一答案前缀时会重复计算。每道题等权。重复标注不能增加集合概率，给定参考以外的同义表达没有计入，这个指标因此仍不等于语义质量或实际解码效果。该指标是本次探索性补充，旧三参考宏平均 CE 同时保留。

**实现与复用规则。**

- 训练模板、生成前缀、受监督标签逐 token 核对；不能只看解码文本。聊天格式属于模型输入定义的一部分。[Transformers 官方说明](https://huggingface.co/docs/transformers/chat_templating)
- 重载全部实验臂和全部种子。检查模型完整哈希、adapter/config/数据/代码来源，并逐参考重现旧概率与 top-1；不要只验证最好的一个 checkpoint。
- top-1 沿用 argmax 的同分规则；top-5 固定 logit 降序、token ID 升序。PyTorch 明确不保证 topk 的并列索引稳定；本轮新诊断烟测抓到的同分实现问题及修正均保留。[PyTorch 官方说明](https://docs.pytorch.org/docs/2.14/generated/torch.topk.html)
- 原始输出、token IDs、各参考概率及官方评分结果持续保存。CMRC 官方任务是篇章抽取式阅读理解；本地公开 dev 应如实命名，不当作官方隐藏 test。[CMRC 官方仓库](https://github.com/ymcui/cmrc2018)
- 同一 `(模型, prompt token IDs, answer token IDs)` 的重复参考应计算一次并缓存；固定精度与组批规则，记录数值敏感性。本次为严格复现旧结果而保留原批次，确实观察到重复答案跨批次的概率差异；另行保存首次值、均值以及逐题最小/最大概率的去重敏感性检查。该包络仅涵盖观察到的重复计算差异，不代替完整 FP32 或任意批次形状下的验证。

**统计与论文表述。** 两个必要对照为 hidden-only 和一个精确等参数 hidden 分配；与较弱对照相比为正，不能替代等预算结果。对每个核心指标先陈述效果量和全部种子，再讨论不确定性。新增诊断的名义区间是描述性的，多指标中出现正区间不等于新的确认性发现。

如果之后要做独立确认，应提前冻结模型/任务、主要指标、最小有意义的增益、训练种子数与停止规则；增加种子应服务于估计精度，而非运行到显著为止。当前 public dev 已被查看，后续结果不能称为新的盲测。无需继续换任务寻找正结果来替代这一证据边界。

已有 CE 证据可支持配置限定的建模增量；“用户可见的生成收益”仍需由对应任务的生成指标独立支持。机制层面还需要对应的 input-only、位置和容量干预，不能由本次指标分解自动推出。
