# 任务为什么调整，以及本轮能验证什么

本轮区分三个问题：任务能否通过后训练学会；只调整边界层能否适配任务；
在普通 LoRA 已经适配后，边界层是否还有超过等参数对照的增量。
后一个问题不能由前两个问题自动推出，最终判断以完整的保留集结果为主。

## 任务修订发生在架构比较之前

第一版完整保存在 [V1 记录](../posttraining_tasks_20260916/README.md)，包含
2,400 条生成输出。当时仅运行 Base 与普通 LoRA，没有观察任何新任务的
A-LoRA 分数。检查发现两项问题：部分 ToolACE 金标准为相对时间补出了
请求中未给出的具体日期；要求模型直接生成实体字符下标，会把位置计数
误差与实体识别混在一起。

第二版据此固定了新的任务表示和评分器，随后才开始所有架构对照：

- 工具调用只保留参数值能在请求中找到字面依据的正调用。训练、开发、
  保留集按工具名称、完整 schema 和规范化请求的连接关系隔离。
  主指标是完整调用集合正确率，保留重复调用的次数；工具名称选择、
  schema 合法性和 JSON 合法性另外报告。这是范围有限的工具选择与
  参数复制任务，不覆盖拒绝调用、时间推理、实际执行或完整 BFCL。
  字面支持检查也不能保证所有语义标注都正确。
- 实体抽取生成类别、原文片段与该片段的出现序号，再用不读取金标准的
  程序还原字符跨度。金标准跨度不变，主指标仍为类别与跨度的 micro F1。
  重复片段、重复预测、非法序号及金标准往返映射均已检查。保留集是
  CLUENER 的 1,343 条公开开发样本，不是官方隐藏测试集提交。

两项任务都进入五种子比较和保留集评测，工具调用的零收益或负结果同样保留。

## 对照与实现核验

使用两个已核验官方文件哈希的预训练 Base。每项任务固定 2,048 条训练数据、
单轮 64 步、LR 2e-4；普通 LoRA、输入侧、输出侧、叠加组和等参数内部 LoRA
各运行五个配对种子。内部 LoRA 的共同初始化和样本顺序逐一核对，叠加组
与扩容对照的可训练参数严格相等：0.6B 为 5,112,832，1.5B 为 9,332,224。

输入侧单独训练只有 33,792 / 50,688 个参数，输出侧为 32,768 / 49,152。
两者均没有内部 LoRA 可训练参数。原始模型张量冻结，梯度和优化器参数范围、
FP32 优化器状态、零残差初始化、提示掩码、保存重载一致性都已核验。
V2 不复用 V1 的已训练适配器；四个 V2 普通 LoRA 先导结果经源码、输入、
训练顺序与权重核验后，作为对应的首个种子复用。

相同任务与模型的正式对照使用相同提示。另有两条固定训练示例的未适配
Base 诊断，用来揭示提示敏感性，其不同提示不能替代正式对照。实体抽取的
零样本 Base 低分不等于模型完全没有实体知识。

## 指标与证据边界

主指标来自真实贪心生成，格式失败与截断样本均留在分母。统一使用原生 EOS
和 512 token 上限；保留集的全部标准答案都在此上限内。批大小从 8 改为 32
前，八个配置共 256 条开发输出的 token 序列及停止标记逐项一致，选择发生在
任何保留集生成之前。保留集阶段不重训，也不按结果选择检查点、提示或子集。

开发集的 [loss 分解](TOKEN_LENGTH_AND_LOSS_DIAGNOSTIC.json) 显示，普通 LoRA
相对 Base 的总 CE 降幅中，EOS 项仅占约 0.03%–0.34%。它消除了此前 SciQ
“主要靠学会停止降低 loss”的特定疑虑；JSON 结构和复制 token 仍包含在
答案 CE 中，所以 loss 改善本身仍不能替代生成内容指标。

八个主对照统一采用五种子配对 t 区间并做 Bonferroni 校正，另报条件于这
五个已训练模型的题目或 API 簇 bootstrap 区间。后者不能替代种子变异。
五种子 t 区间依赖其参数假设；同时给出逐种子差值，不能只看均值或显著性标签。
单侧边界层的效果作为次要描述结果，不能替代叠加组的主对照。

这是两个相关模型、少量训练数据和共同学习率下的证据。尚未分别搜索各方法
的最佳超参数，也不能排除公共数据的预训练暴露。因此结论应限定到实际任务
和设置，不能宣称通用后训练优势、最优参数效率、新知识注入或所有任务均增益。
两任务的语言和数据来源也不同，且本轮叠加组同时启用输入与输出侧；因此任务间
差异不足以确定收益机制，也不能区分叠加收益具体来自哪一侧。
