# Qwen3.5 首批损失差异：受控复现与修正验证

本次控制实验已经证明：只改变原生 FLA 的 L2 归一化执行配置，就能精确复现一项旧运行的首批损失差异。它提供了充分的数值机制，但旧进程没有记录实际选中的配置，因此不能断言它当时用了哪一个配置；也不能直接据此解释最终下游指标的涨跌。

异常来自旧 0.8B 矩阵的 WikiSQL 严格等参数 LoRA，seed7600、学习率1e-4：更新前首32条训练样本损失为1.2254207134246826，其他已检查的同种子运行通常为1.2234999686479568，相差0.001920744776725769。共享 LoRA 初始张量、冻结基座、样本顺序均相同。异常运行自身的两次前向与反向完全一致，说明“同一进程内重复成功”不足以排除跨进程的计算差异。

在完全不更新权重的条件下，固定其他执行配置，逐一改变 `fla.modules.l2norm:l2norm_fwd_kernel` 的官方候选配置。BT=8、warps=8，以及BT=16、warps=16，均精确复现了原异常运行的**全部16项微批次损失贡献**，不仅是汇总损失。stage均为2、CTA均为1。原始证据在 `CONTROLLED_REPRODUCTION.json` 和 `l2norm_configs/RESULTS.json`。

安装的 FLA 0.4.2 使用 Triton 自动计时选择计算配置；当前 Triton 3.2 的自动调优缓存位于进程内。不同配置采用不同的归约与分块方式，在有限精度下不必逐位等价。同一个进程可以一直沿用自己的配置，因而局部重复能通过。单独改变输出计算和三角求解的配置也出现了其他损失值，说明只固定一个归一化配置不足以覆盖所有已观察的数值自由度。三角求解此次使用IEEE配置，不能把该现象直接归咎于TF32。

修正采用进程内固定12个原生FLA内核配置，所有选择均来自已安装版本的合法候选；同时显式固定PyTorch确定性算法、cuBLAS工作区、cuDNN策略，关闭TF32和低精度矩阵乘归约。不修改公共安装库，也不按开发/确认集成绩挑配置。此次同时固定多个数值设置，因此未来旧/新结果的差异不能只归因于L2归一化。

在0.8B WikiSQL的前256条训练样本上，分别以严格等参数LoRA和LoRA＋双侧aLoRA运行八步更新，GPU5和GPU6使用两个独立进程。两种方法均达到八步逐步损失、梯度范数、全部更新前梯度哈希、全部更新后适配器哈希完全一致。冻结基座也保持不变。记录在 `fixed_budget_gpu5/6` 和 `fixed_both_gpu5/6`；这些探针没有读取开发/确认集效果，其权重不会复用到正式实验。

这仍然是有边界的验证：一个模型、一个任务的八步一致不能证明所有模型或全部训练轨迹均具有跨设备确定性。新的四尺寸矩阵还会为每个任务、每个准入种子生成无更新的训练首批参考值，由另一张显卡上的独立进程核对所有三组，正式运行在更新前必须精确匹配16项损失，并通过重复反向的全部梯度一致性检查。发现任何违反则停止新任务准入，保留已产生的记录进行诊断。

旧矩阵暂停后没有中断正在运行的训练；五个活动任务均正常退出，再完成独立审计。0.8B/2B/9B分别保留24/11/6项完成记录，随后作为不完整的旧设置实验归档。此前完整封存的4B研究也保留。新的0.8B、2B、4B、9B四组使用共同修正设置，全部重新训练，不拼接任何旧checkpoint或预测。完成后再判断是否存在稳定叠加收益。

补充核验（2026-09-20 01:30）：新的统一设置矩阵已经运行到原0.8B异常规格。对照归档记录，完整适配器初始化、共享LoRA初始化、冻结基座及全部训练顺序均相同；新运行首批为1.2234999686479568，16项微损失全部匹配独立参考。证据见 `OLD_OUTLIER_FRESH_INITIAL_CHECK.json`。这是整个矩阵统一重跑中的一次初始状态核验，不是选择性替换异常运行，也尚不是最终任务指标比较。
