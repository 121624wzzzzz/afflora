# 下一轮实验建议：直接 E/U LoRA 对照优先

状态：设计与参数/代数核对已完成；本目录没有启动新训练。此前 rank8 的48次正式实验、16次短训练已完成。

## 1. 目前最关键的证据缺口

现有下游结果支持：在所测条件下，边界 aLoRA 叠加到 hidden LoRA 后仍有收益。它尚不足以支持：同一 E/U 位置，aLoRA 比普通词表矩阵 LoRA 更有效。历史 RESULTS_SO_FAR.md 的 Claim1b 已有 vocab-dim LoRA 对比，但主要是旧语言模型 eval_loss；不能直接充当新 CLUENER/WikiSQL 的任务效果对照。

这里的普通 LoRA 指直接对 embedding / lm_head 权重做低秩更新。若只是给相同位置的 d×d 恒等映射加 LoRA，其无bias线性部分就是当前 aLoRA 的低秩残差映射，不是独立架构基线；该比较应作为bias消融。

行向量约定 E∈R^(V×d)、U∈R^(d×V)：aLoRA 的有效更新可以写成 ΔE=(EA)B+1b^T、ΔU=C(DU)，其中输入bias是可选项。这说明其线性部分是受基座词表矩阵约束的低秩权重更新。普通LoRA的词表侧因子自由训练。有效更新可因式分解不表示二者优化动力学相同。小矩阵双精度代数检查见 DESIGN_CHECK.json。

## 2. 第一优先级：同位置、同 hidden 主干的直接对照

首轮保留 Qwen2.5-7B / Qwen3-8B（untied），两个既有核心任务。固定 H 的rank、target modules、训练样本、训练时长和评测。比较 H、H+Aff(E)、H+Aff(U)、H+Aff(E+U)，及 H+LoRA(E)、H+LoRA(U)、H+LoRA(E+U)。aLoRA r8/r16已有结果先核验复用，不冒充新重复。

先加入普通 LoRA rank1 的三个放置方案：2模型×2任务×3方案×3种子=36次新正式训练。这是结构筛查的候选规模，不包含短训练检查、验证集调参或后续确认的开销；不能把36次误当全部研究预算。阶段性审阅技术检查与已完整的预定对比，不按测试集正负删配置。

所有方法必须保持同一 H 方案。主比较同时记录共同学习率结果；若用验证集调边界学习率，则每种方法给相同搜索预算，并为 aLoRA 同样调参。模型选择仅用验证集，最终配置冻结后跑测试。明确普通embedding LoRA与linear LoRA的初始化方向，检查零更新、首步梯度和优化器范围。训练mask、native EOS、输出解码和官方评分继承已审计协议。

bias处理：原 aLoRA E 有d维共享特征bias，而普通LoRA通常没有；保留标准无bias基线，同时做 aLoRA 去bias，必要时补普通LoRA+同样的d维bias。所有参数计数包括bias；不能把加bias后的对照仍称纯标准LoRA。

## 3. 参数预算不能用rank替代

普通词表矩阵LoRA每侧 q(V+d)；aLoRA E为(2r+1)d、U为2rd，独立双侧为(4r+1)d，tied共享为(2r+1)d。均仅计算边界额外参数，H保持完全相同。

|untied模型|普通LoRA双侧各r1|aLoRA双侧各r16|普通LoRA单侧r1|aLoRA E16|aLoRA U16|
|---|---:|---:|---:|---:|---:|
|Qwen2.5-7B|311296|232960|155648|118272|114688|
|Qwen3-8B|312064|266240|156032|135168|131072|
|Llama3.1-8B|264704|266240|132352|135168|131072|

表中普通LoRA无额外bias。Llama8B的双侧预算只差1536，但仍不标为严格等参。若增加普通LoRA E的d维bias，需额外计入4096参数。

在当前aLoRA低预算下，普通LoRA的整数rank可能连1都无法容纳。优先报告真实参数-效果关系：普通LoRA r1/r2 与 aLoRA r8/r16/r32 的预设预算点；必要时增加一个同rank但高预算的普通LoRA作为容量参考。最近的上方预算也可作为强对照，明确实际差额。不可添加无效参数补齐；不可削减hidden rank来凑数后称同结构对照。若使用冻结部分词表因子或稀疏mask严格配额，它是受限LoRA，必须与标准LoRA分列。

## 4. 第二优先级：seed和独立确认

新共享/rank8/untied架构块目前主要3种子；旧主线部分条件已有5种子，不重复训练已有合格对照。选定并公开少量主比较，统一到5个配对种子；预算允许时对关键结论另设冻结配置后的独立确认批次。补旧3个种子到5个属于扩展，并非五个全新独立确认。

不要只为负面条件加seed，也不要看到显著就停。预先固定种子数、比较族与统计口径。训练随机seed仅衡量同一数据划分上的优化波动；后续可给关键条件增加独立训练子集或独立测试数据，以检验样本选择敏感性。

## 5. 第三优先级：有目的地补模型

已有Qwen两系列八尺寸及Llama1/3/8B，继续重复主线尺寸的收益低于补直接基线。优先扩展当前尚未覆盖的架构对照：

- Qwen3-4B（tied）：共享 aLoRA r8/16/32 和真正保持有效权重绑定的普通共享LoRA。普通共享r1为154496参数，aLoRA共享r32为166400；明确非严格等参。
- Llama3.1-8B（untied）：普通E/U LoRA与aLoRA单侧/双侧。词表较小，r1标准LoRA与r16 aLoRA预算非常接近，且能检验跨家族。必须选定同一Llama协议，不能混用旧2e-4测试集与后续4e-4/新保留集的数值。
- 如还需 tied 的跨家族确认，再考虑已有 Llama3.2-3B。不要同时展开全部rank×位置×型号的全排列。

tied对照必须共享一份有效词表更新，输出使用相应转置；只保留原基座weight指针绑定却新增两套独立更新，不算有效绑定。untied各侧独立，不强行共享。保持此前不扩充Gemma/Qwen3.5的范围决定。

## 6. 任务范围与结论

CLUENER/WikiSQL是根据既有正结果选择的核心任务。更广泛的泛化主张需要冻结方案后在未用于选结构的任务或独立数据上确认；已有ANLI等负结果应保留。优先把“比同位置普通LoRA是否更有效”“小预算是否保留收益”“哪一侧贡献收益”回答清楚，再增加同质模型规模。

LoRA原始定义参考：https://arxiv.org/abs/2106.09685 。本报告的aLoRA公式与预算来自本地实现及模型config核算。
